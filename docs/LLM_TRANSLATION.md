## 翻译与判断规则

- 每条查看英文和关联说明或脚本上下文，再撰写完整中文。英语显示正文为依据；日文内部名称可能是旧版本残留，不能据此悄悄改写英文内容。
- 不确定的专名、缩写、术语、含义和语境先核对日文，仍有疑点再交给用户判断。区分本地内部日文标签、正式日文显示文本及外部日文资料，不能冒称完整运行过日文版。相关条目待定，其他条目继续；用户确认后记录进术语决策文件。
- 人物属性栏保留英文缩写的约定继续生效。完整词语 Force 等按已确认术语翻译，缩写 FOR 等仍保留原样。
- 检查控制标记、原文哈希、数值、正负号、百分比和排列顺序。自动检查不等于语义验收，重译条目标注为“本聊天模型已重译 · 待验收”，不冒充人工校对。
- 不启动、不操作、不安装到实际游戏；每批译文独立保存，后续按新版本重建补丁。

## 开发进度与文件

- `translations/translation-workflow.json`：用户要求、术语决策、待判断问题。
- `translations/llm-batches/0001.json` 至 `0061.json`：每条英文、新译文、旧译文、原文哈希与模型翻译来源；新批次还保存日文核对来源。
- `translations/llm-batches/0003-retained.json`：用户确认保留的版本标记，独立于模型翻译数量统计。
- `translations/user-overrides.json`：构建使用的独立译文修订层。
- `tools/llm_workflow.py status`：统计重译、待判断、旧稿及保留缩写，不能把旧稿计为模型已重译。
- `tools/llm_workflow.py queue --limit 30`：导出下一批原文和关联文本；此工具只整理队列，不会自行调用模型。
- `tools/llm_workflow.py commit <batch.json>`：在检查原文、标记、数字和待定问题后合入模型已撰写的译文。程序不会调用本地翻译模型，也不会伪造在线 API 调用。
- `tools/llm_workflow.py queue --limit 500`：短文本按约500条整理，上限600条，并按关联组补齐边界。当前普通队列与未答复问题均为空；39项暂留问题保留到最后终审。
- `tools/llm_workflow.py final-review`：刷新 `docs/final-review-queue.json`，集中保存待定问题、受影响的英日中对照、中文稿状态和定位。不是每条受影响记录都已重译。

第五批专名与英日差异的证据及用户决定见 [本批核对记录](term-research-0005.md)。0063批阅验证已完成：53项 Python 测试、编辑器核心测试、隔离 Edge 浏览器测试全部通过；未操作游戏。编辑器草稿现只把相对内置译文的变更写入 `localStorage`，避免12,040条完整元数据超过浏览器存储配额。
