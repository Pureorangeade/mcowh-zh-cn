## 最方便的方式

1. 打开项目 `editor/汉化译文编辑器.html`，用 Edge 或 Chrome 浏览，无需联网、安装 Python 或翻译模型。旧0.2.1压缩包内的编辑器不包含本轮三语与终审功能。
2. 在搜索框输入英文名、中文译文或一句话中的几个字；也可以按物品、技能、剧情等分类筛选。
3. 左侧为只读英文，中间为只读日文原文及来源，右侧中文可修改。已载入11,985条日版显示原文，按结构对齐，英日含义差异仍需核对；数据库内部日文标签单列在下方，仅供查证。图片文字及3个日版空字段仍明确标记缺失。长文本可点“阅读预览”隐藏控制标记；编辑时点“返回编辑”。
4. 修改自动存入当前浏览器的草稿。完成一批后点右上角 **导出修订 JSON**，保存“汉化译文修订.json”。
5. 把这个 JSON 文件发回聊天，我会将修订合入新版补丁。重新打开编辑器时，也能用“导入修订”载入保存的文件。

编辑器和修订文件不会自动更改游戏。译文合入、重建并重新安装补丁后，游戏里才会显示新内容。只做文字校对时不用关闭游戏。

不确定某条内容时，展开“语境不确定？暂缓至最后终审”，填写疑点，点击“整条暂缓，保留原文”。中文草稿保留，终审标记与译文一起导出、导入；合入后构建会使用该条英文。决定采用中文后点“取消整条暂缓”。术语级暂缓会显示提示，保留相关英文词语，其余内容可继续翻译。

人名继续暂留英文，18项人名记录与F18—F21共22项终审问题可在“最后终审”筛选中查看。Sp.、and stop和成长之雾末句已根据0065决定处理，不再作为未决问题。具体以当前FINAL_REVIEW.md及编辑器标记为准。新增正文可筛选“序章与结尾”，或搜索db/72/编号。

浏览器草稿并不是 HTML 文件本身。换浏览器、移动文件、清理浏览器数据前，请先导出 JSON；跨设备时使用 JSON 转移。初稿升级仍按英文原文哈希匹配，原文一致的修订可以继续导入。

## 避免误改

- 另有63条旧提取器误收录的reset程序指令，现已锁定并保留原样，不计入待翻译或日文显示正文数量。
- 当前共 12,238 条：12,008 条主文本、43 条系统提示和初始文本、187 条图片文字。它是已识别内容的编辑目录，不代表全游戏已完整提取。
- `\c[...]`、`\img[...]`、`<PLAYER>`、`$tmp1` 等是颜色、图标或变量。保留它们的内容、数量和先后次序；检查失败时不能导出。定位详情中可查看需要保留的标记。
- 人物面板19项属性对应29字段已按用户确认改为中文且可编辑，MOV为“移速”。其余50条英文缩写模板仍按约定保留；不要扩大到HP/ST/EN/Lv/Exp/WT或HUD。状态、能力、详情等栏目标题仍为中文。
- 普通对话允许人工调整换行，但游戏内是否合适仍需截图确认。选项空格会转成下划线，以符合游戏脚本格式；图片文字只允许一行，长文字会在构建时自动缩小。
- 导入按稳定编号合并，不按屏幕上出现的顺序替换。同一条修订以后导入的内容为准；未知编号、原文不匹配、重复编号或损坏标记会整批拒绝。
- 所有模型译文仍需语义校对。编辑器检查控制标记，不能判断翻译是否准确。图片的英文栏为按图片整理的标题，普通文本为直接提取的英文原文。

## 自行合入与重建（开发用）

玩家只需导出JSON。开发者可运行python tools/editor_data.py --import-file "汉化译文修订.json"合入，随后按DEVELOPMENT.md更新源绑定批次、允许变更范围、构建并测试新版。当前build_story_compat.py使用冻结0.3.3基线，不能仅导入任意修订后就默认自动进入安装包。

没有修改图片时，不重新渲染文字图；没有新增字形时，不重画字体。英文、日文来源及控制标记不随中文修订改变。
