## 最方便的方式

1. 打开项目 `editor/汉化译文编辑器.html`，用 Edge 或 Chrome 浏览，无需联网、安装 Python 或翻译模型。旧0.2.1压缩包内的编辑器不包含本轮三语与终审功能。
2. 在搜索框输入英文名、中文译文或一句话中的几个字；也可以按物品、技能、剧情等分类筛选。
3. 左侧为只读英文，中间为只读日文原文及来源，右侧中文可修改。已载入11,951条日版显示原文，按结构对齐，英日含义差异仍需核对；数据库内部日文标签单列在下方，仅供查证。图片文字及3个日版空字段仍明确标记缺失。长文本可点“阅读预览”隐藏控制标记；编辑时点“返回编辑”。
4. 修改自动存入当前浏览器的草稿。完成一批后点右上角 **导出修订 JSON**，保存“汉化译文修订.json”。
5. 把这个 JSON 文件发回聊天，我会将修订合入新版补丁。重新打开编辑器时，也能用“导入修订”载入保存的文件。

编辑器和修订文件不会自动更改游戏。译文合入、重建并重新安装补丁后，游戏里才会显示新内容。只做文字校对时不用关闭游戏。

不确定某条内容时，展开“语境不确定？暂缓至最后终审”，填写疑点，点击“整条暂缓，保留原文”。中文草稿保留，终审标记与译文一起导出、导入；合入后构建会使用该条英文。决定采用中文后点“取消整条暂缓”。术语级暂缓会显示提示，保留相关英文词语，其余内容可继续翻译。

已暂留英文的Zeukrees、Pluton、Auris、Sp.和and stop进入最终终审队列，过程中不反复询问。人物栏永久保留的缩写不需要终审。成长之雾的末句也按用户决定保留英文至终审，日文证据现已可对照。

浏览器草稿并不是 HTML 文件本身。换浏览器、移动文件、清理浏览器数据前，请先导出 JSON；跨设备时使用 JSON 转移。初稿升级仍按英文原文哈希匹配，原文一致的修订可以继续导入。

## 避免误改

- 另有63条旧提取器误收录的reset程序指令，现已锁定并保留原样，不计入待翻译或日文显示正文数量。
- 当前共 12,204 条：11,974 条主文本、43 条系统提示和初始文本、187 条图片文字。它是已识别内容的编辑目录，不代表全游戏已完整提取。
- `\c[...]`、`\img[...]`、`<PLAYER>`、`$tmp1` 等是颜色、图标或变量。保留它们的内容、数量和先后次序；检查失败时不能导出。定位详情中可查看需要保留的标记。
- 人物属性中的 STR、VIT、AGI、INT、WIL、CHR、ATK、ACC、ID 等 79 条缩写或组合模板已按你的要求锁定。状态、能力、详情这些栏位标题仍为中文；普通物品、技能和说明可以修改。
- 普通对话允许人工调整换行，但游戏内是否合适仍需截图确认。选项空格会转成下划线，以符合游戏脚本格式；图片文字只允许一行，长文字会在构建时自动缩小。
- 导入按稳定编号合并，不按屏幕上出现的顺序替换。同一条修订以后导入的内容为准；未知编号、原文不匹配、重复编号或损坏标记会整批拒绝。
- 所有机翻仍需语义校对。编辑器检查控制标记，不能判断翻译是否准确。图片的英文栏为按图片整理的标题，普通文本为直接提取的英文原文。

## 自行合入与重建（开发用）

玩家校对只需上面的 HTML 和 JSON，不需要执行这里的命令。开发环境准备完成后，在项目目录运行：

```powershell
python tools/editor_data.py --import-file "汉化译文修订.json"
python tools/render_textures.py
python tools/build_full.py --game work/clean-fixture
python tools/editor_data.py
python -m unittest discover -s tests -v
node tests/editor_core.test.js
python tools/bundle.py --source work/clean-fixture --build build/full
```

修订独立保存在 `translations/user-overrides.json`，不覆盖机翻底稿。重复导入合并已有修订并自动备份；构建会重验原文哈希和标记、重新生成所需字形。使用原始干净副本构建，不能把已装补丁的资源当作原版。安装器和玩家包还需按 README 中的验证与打包步骤重新生成。
